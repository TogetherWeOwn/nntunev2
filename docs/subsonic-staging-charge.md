# Staging Subsonic construction charge

This is an ownership inventory for the unmounted staging candidate, not staging admission or a limit on isolate memory. The [Worker toolchain pins](../.github/worker-toolchain.json) select Rust 1.98.1 for `wasm32-unknown-unknown`; the API lockfile pins Worker 0.9.0 and wasm-bindgen 0.2.130. The normal/default/production mount stays off.

`ConstructionBudget` carries one cumulative 8 MiB ledger. For each nonempty allocation it checks `capacity × size_of::<T>()`, adds the pinned dlmalloc chunk overhead (4 bytes), rounds up to 8 bytes with a 16-byte minimum, then adds 8 bytes for allocator slack. Unsupported alignment and arithmetic overflow fail closed. `allocate_exact` charges before `try_reserve_exact` and verifies the reported capacity before filling. A vector charge includes all inline row/element headers (including optional fields and the headers of owned strings); each string's backing bytes are charged separately. Dropped allocations are not refunded. Moving an already charged buffer or a nested value does not charge it twice.

| Phase | Simultaneous Rust owners and charge |
| --- | --- |
| Raw request and permit | `StagingInput` retains exact serialized path/query capacities and one 8 KiB form reservation on its first nonempty chunk. The raw request/chunks stay on the platform side. GET/POST, 1 KiB path, 8 KiB aggregate headers, query/form ceilings and declared size are checked before the corresponding Rust copy. `begin` takes the single non-waiting construction slot after bounded collection and before credentials/DB. The permit travels with the ledger in `StagingConstruction`. The unmounted adapter opens the authorized app client only inside that scope, verifies the credential, then checks the fixture principal before any catalogue work. It keeps the permit through Worker response preparation, not platform input buffering or returned responses. |
| Credentials and account | Charge decoded key/value buffers before copying. The app DB projects bounded credential text and ciphertext; charge copied ID/owner/name/scope, optional HMAC text, wrapped key and ciphertext. Charge digest/reindex strings, AAD and the two AEAD ciphertext-capacity copies, salted input, padded MD5 block buffer and hex output. Principal strings move from the verified record. Existing authentication can commit rate admission and conditional credential completion (last-used and, when needed, reindexing) before fixture refusal; this adapter adds no write primitive. Account projection copies username once and email twice on the same ledger. Inline parameters, case-normalization scratch and role flags do not reserve heap storage. |
| Membership | Charge composed SQL, exact release/pair vector backing (including inline `String` headers), and each normalized ID's capacity. Sort/dedup in place. The owner-scoped release/pair count and source-text probe runs in the same read-only repeatable-read transaction as the fetch. |
| Mirror | Charge probe SQL, borrowed pair-column vectors, the full projected `ArtistDbRow`/`ReleaseDbRow`/`TrackDbRow` vector capacities, and copied text, including optional fields. Use the remaining membership-and-mirror 256 KiB source-text budget, 1,024 rows per result and 1 KiB per field at the same-state DB probe. Empty membership never invokes the mirror connector. The app and mirror transactions are independent, not globally atomic. |
| Snapshot mapping and ordering | Charge a second owned raw-row copy and all output model vector/string capacities before mapping. Occurrence resolution borrows the original tracks; all projected originals can drop without refund after graph construction. Snapshot order uses stable in-place insertion under a separate comparison/probe budget; no heap sort scratch or hash tables. The current mirror supplies a year, not release/curation dates. Catalogue comparisons respect known-date/tie order where those fields are present; absent dates are not synthesized. |
| Dispatch and response graph | Reparse query/form into a charged vector of string pairs; charge both decoded and lossy UTF-8 buffers when they overlap. Use borrowed member rows, charged grouping/list/search reference vectors, and in-place sorting with explicit ties. Unicode matching charges the starting lowercase buffer and each predicted relocation capacity using the pinned Rust growth rules. Reserve exact `Value` list/map storage and charge each owned key and text backing buffer; do not clone a whole model or page, or allocate from a requested offset/count without capping it to admitted rows. |
| Document and Worker conversion | Walk the immutable graph to count framing, escaping and JSONP callback bytes before allocation. Enforce a separate 256 KiB output cap, charge once and write directly into that exact buffer. Fixed capacity/error rejections have separately bounded static bodies of at most 1 KiB, never interpolating input or a JSONP callback. Worker conversion consumes the Rust body and creates a JS `Uint8Array` copy, outside the Rust ledger. |

**PostgreSQL ownership boundary:** `tokio-postgres` 0.7.18 uses a row stream for `query_typed_one`/`query_typed_opt`; staging uses these for fixed-width probes and singleton auth/account reads. For pages, a same-state probe admits a row count and aggregate text bytes. The caller charges and reserves the projected vector before starting `query_typed_raw`, decodes each borrowed row into that storage, and rejects extra rows, early EOF, or driver errors without returning a partial page. No staging caller retains a `Vec<Row>`. Driver transport/protocol buffers, row metadata, transient row objects and other driver internals are outside the ledger; a deadline does not prove cancellation or teardown. Other exclusions are platform-parsed request metadata, future/runtime and transport state, allocator resident pages, linear-memory high-water mark, and undocumented response constructor/transport copies or retention. The single permit is **construction-only**; handler return, EOF or cancellation is not evidence about the lifetime of those exclusions.

The Actions Worker job runs `run_ledger_tests` on the pinned release WASM artifact. Its synthetic fixtures cover bounded collection, response conversion, busy refusal, and permit recovery after the app-open deadline expires. A test-only verified principal also exercises fixture authorization before account/catalogue reads and charged folder dispatch. These fixtures do not connect to PostgreSQL or prove staging isolation. Exact/one-short cases use injected ceilings, not a load-to-exhaustion run. Record the jobs for the exact integrated head before calling the candidate verified.
